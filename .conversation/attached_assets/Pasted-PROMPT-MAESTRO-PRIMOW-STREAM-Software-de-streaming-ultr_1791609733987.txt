PROMPT MAESTRO — PRIMOW STREAM

Software de streaming ultraligero para Windows

Actúa como un equipo senior de ingeniería de software especializado en C++20, aplicaciones nativas para Windows, Qt 6, libobs, NVIDIA NVENC, DirectX, captura de videojuegos y procesamiento audiovisual de baja latencia.

Tu misión es desarrollar y entregar un programa de streaming completamente funcional, instalable y ejecutable en Windows, llamado PRIMOW STREAM.

NO quiero una página web, una PWA, una maqueta visual ni una aplicación que dependa de Replit para ejecutarse.

Quiero un software independiente que pueda instalar en mi PC y utilizar como alternativa a OBS Studio, pero con una interfaz muchísimo más básica, intuitiva y ligera.

La prioridad absoluta es transmitir videojuegos competitivos con la menor pérdida de rendimiento posible.

---

1. OBJETIVO DEL PRODUCTO

Crear un software con estas características:

- Extremadamente ligero.
- Muy bajo consumo de CPU.
- Uso eficiente de RAM y VRAM.
- Codificación por hardware.
- Mínimo impacto posible en los FPS de los videojuegos.
- Baja latencia.
- Funcionamiento estable.
- Interfaz moderna y minimalista.
- Configuración inicial muy sencilla.
- Un solo botón para comenzar a transmitir.
- Instalación local en Windows.
- Funcionamiento completamente independiente de Replit.
- Sin suscripciones.
- Sin servidores intermediarios.
- Sin publicidad.
- Sin telemetría innecesaria.

Principio fundamental:

No quiero desarrollar otro OBS con cientos de configuraciones.

Quiero aprovechar un motor de transmisión profesional ya existente y construir encima una aplicación mucho más simple.

La aplicación debe concentrarse en hacer pocas cosas, pero hacerlas extraordinariamente bien.

5. SISTEMA DE STREAMING REAL

Implementar transmisión directa desde el PC hacia Kick.

Configuración predeterminada:

Parámetro| Configuración
Plataforma| Kick
Resolución| 1920 × 1080
FPS| 60
Codec| H.264
Encoder| NVIDIA NVENC
Bitrate inicial| 6.000 kbps
Bitrate máximo| 8.000 kbps
Rate Control| CBR
Keyframe Interval| 2 segundos
Perfil H.264| Main
Multipass| Single Pass
Audio| AAC estéreo
Frecuencia de audio| 48 kHz
Bitrate de audio| 160 kbps

Seleccionar un preset NVENC compatible que priorice bajo consumo y buena calidad.

Permitir comparar presets como P4, P5 y P6, si están disponibles, para elegir el mejor equilibrio entre calidad y rendimiento.

No aplicar valores incompatibles con Kick.

Permitir modificar el bitrate desde un menú avanzado.

Conexión a Kick:

Crear una sección inicial donde el usuario ingrese:

- URL del servidor de transmisión.
- Stream Key.

Permitir copiarlas directamente desde el panel de creador de Kick.

No inventar credenciales ni pedir contraseñas de la cuenta Kick.

Guardar la clave de forma segura usando DPAPI o Windows Credential Manager.

Nunca almacenar la Stream Key en texto plano, archivos públicos, logs o repositorios Git.

Nunca enviar la clave a servidores de Replit.

Incluir prueba de configuración local y validación de formato, pero no iniciar una transmisión real sin una acción explícita del usuario.

Implementar los estados:

Desconectado → Conectando → En vivo → Reconectando → Finalizado.

Manejar correctamente interrupciones de conexión.

No cerrar el programa si el servidor de streaming deja de responder.

6. OPTIMIZACIÓN EXTREMA

Esta es la sección más importante del proyecto.

PRIMOW STREAM debe priorizar siempre los recursos del videojuego por encima de la aplicación de streaming.

Implementar todas las optimizaciones técnicamente seguras y verificables.

GPU

- Utilizar NVENC dedicado.
- Evitar procesamiento adicional innecesario.
- Reducir copias de frames entre GPU y CPU cuando sea posible.
- Reducir transferencias innecesarias de texturas.
- Minimizar conversiones de formatos.
- Utilizar aceleración por GPU para el escalado cuando resulte más eficiente.
- Evitar una segunda codificación para la vista previa.
- Evitar efectos gráficos innecesarios.
- No utilizar filtros de video predeterminados.
- Detectar saturación del procesamiento de video.
- Evitar un uso de GPU que provoque pérdida importante de fluidez en CS2.

CPU

- Minimizar procesos e hilos innecesarios.
- No utilizar codificación x264 cuando NVENC funcione.
- No implementar procesamiento intensivo en la interfaz.
- Evitar comprobaciones excesivamente frecuentes.
- No utilizar motores web embebidos.
- No realizar análisis de imagen innecesarios.
- No utilizar prioridades extremas que perjudiquen al juego.

RAM

- Mantener buffers limitados y reutilizables.
- No duplicar innecesariamente frames.
- Liberar correctamente recursos audiovisuales.
- Evitar fugas de memoria.
- No conservar capturas de video innecesarias.

Vista previa

Incluir un modo:

MÁXIMO RENDIMIENTO

Este modo debe:

- Ocultar la vista previa mientras se transmite.
- Reducir actualizaciones visuales de métricas.
- Desactivar efectos decorativos.
- Mantener solamente el procesamiento necesario para transmitir.
- Liberar recursos de renderizado de la interfaz que ya no se utilicen.

Asegurar que ocultar la vista previa no interrumpa la captura ni la transmisión.

Objetivos de rendimiento

Intentar mantener:

- Uso de RAM lo más bajo posible.
- CPU al mínimo práctico.
- Sobrecarga de GPU reducida.
- Buena estabilidad de frametimes.
- Streaming estable a 1080p60.

No presentar porcentajes o cifras inventadas.

Implementar benchmarks para demostrar los resultados.

- Scripts de compilación.
- Configuración de empaquetado.
- Documentación.
- GitHub Actions para Windows.

Crear un workflow:

.github/workflows/windows-build.yml

Que realice:

1. Checkout del código.
2. Instalación de herramientas necesarias.
3. Preparación de dependencias.
4. Compilación en Windows x64.
5. Validación de los binarios.
6. Empaquetado.
7. Generación del instalador.
8. Generación de ZIP portable.
9. Publicación de artefactos descargables.
10. Reporte de errores y registros de compilación.

Utilizar un runner Windows compatible y MSVC.

Mantener versiones de dependencias reproducibles.

No reemplazar silenciosamente la aplicación nativa por un proyecto web porque resulte más fácil de ejecutar en Replit.

Si Replit no tiene acceso a un entorno Windows, usar GitHub Actions o dejar una compilación Windows reproducible preparada.

Si no cuentas con acceso a GitHub, entregar los archivos del workflow, el proyecto exportable y las instrucciones exactas para ejecutarlo.
